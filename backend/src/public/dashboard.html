How it works How to use

What to click, in order, to get a stream onto your website.

  1. 1

    Create a channel

    Click "+ Create channel" on the Channels page and name it after the room, service or camera it's for. Each channel has its own stream key, settings and outputs.

  2. Connect your encoder

    Copy the channel's RTMP URL and stream key into OBS, vMix or whatever you stream from, then press "Start Streaming" there. There's no "go live" button in this app: the channel goes live as soon as your encoder connects.

    2
  3. 3

    Put the player on your website

    On the channel page, click Website HTML, copy the code and paste it into your site's HTML. You can leave it there all the time. It only downloads video once a visitor presses play.

  4. Send it to other places too

    Click "+ Add output" to send the same stream to YouTube, a Facebook Page or any custom RTMP address, or to make a Public Link people can open directly. Each output has its own on/off switch.

    4
  5. 5

    Turn on recording if you want a copy saved

    Switch on "Record streams" before you go live. After you stop, the recording appears on the Recordings page, usually within 5 to 30 minutes, ready to play back or download. Recordings are never public.

  6. Add cover and thumbnail images

    On a channel's page, upload an offline cover, shown while you're not live, and a live thumbnail, shown while you're live until someone presses play. You can upload several of each and click one to use it.

    6
  7. 7

    Check who's watching

    The Stats page lists who watched each channel on your website: one row per viewer, with their device type, IP address and rough location. It also shows views on YouTube and Facebook. Filter by channel or date, and export to CSV, Excel or PDF.

  8. Rename or delete a channel

    Both buttons are at the top of the channel's page. Deleting a channel can't be undone: its stream key stops working and all its outputs go with it.

A script that pretends to be many viewers at once, to see how the site copes. It makes the same requests a real player makes (status checks, playlist and video segment requests, and heartbeat pings) without downloading the full video. Run it on your own computer, not the server.

Download load-test.js

How to run it.

  1. 1

    Download the script

    Click the download button above. You'll need Node.js 18 or newer on your computer, from nodejs.org.

  2. Start a test stream

    The channel you're testing needs to be live, with a real stream or a looping video from OBS, so the script has something to fetch.

    2
  3. 3

    Run it

    Open a terminal in the folder you downloaded it to and run node load-test.js. It asks for the password (smithton), then the channel ID (the long ID in that channel's embed code), how many viewers to pretend to be, how long to run, and how many seconds to take adding them. Press Enter on any of the last three to use the suggested value.

  4. Watch it run

    It shows a running count of requests, then a summary for each type of request when it finishes: the error rate and the average, typical and slowest response times. Errors or response times going up are the sign the site is struggling.

    4
  5. 5

    Clean up afterwards

    Stop the test stream, then go to Stats, filter to today's date, select all and delete. Otherwise the pretend viewers stay in that channel's numbers, since the app can't tell them from real ones.

What happens on the server, from your encoder to a viewer's screen.

  1. 1

    Your encoder pushes video in over RTMP

    OBS, vMix or whatever you use sends live video to this server using RTMP, a protocol made for streaming. The server checks your channel's stream key when you connect. Anyone with the key can stream to your channel, so treat it like a password.

  2. The server converts it to HLS in real time

    The server repackages the video into HLS as it arrives: a few seconds at a time, saved as small files, with a playlist that always points to the newest ones. Browsers can play HLS over ordinary HTTPS without a plugin, which is why most video sites use it.

    2
  3. 3

    Viewers never touch the ingest server directly

    The RTMP server can't be reached from outside to watch video. The backend fetches the HLS files internally and serves them on the same domain as the rest of the site, so a viewer's browser only ever talks to this website.

  4. The embed player checks in, then pulls video on demand

    The player on your website asks the backend every few seconds whether the channel is live. It only downloads video once someone presses play, so a player nobody is watching uses almost no bandwidth.

    4
  5. 5

    The server copies your stream to each output

    For each output that's switched on, the server starts a separate process that copies the incoming video, unchanged, to that destination (YouTube, Facebook or a custom RTMP address) for as long as you're live. For YouTube and Facebook it first creates the broadcast with your title. Copying without re-encoding uses very little of the server's CPU, and your encoder only ever sends one stream.

  6. Recordings are saved on the server, then moved to cloud storage

    With recording on, the incoming video is also written to a file on the server's disk. When you stop, the server converts it to a normal video file you can skip through, uploads it to Cloudflare's cloud storage and deletes its own copy, so finished recordings don't take up space on the server.

    6
  7. 7

    Stats come from the player checking in

    While someone watches on your website, their player checks in with the backend every so often. The backend records their IP address, a rough location worked out from it, and whether they're on a phone or computer. Viewers never sign in, so there are no names. YouTube and Facebook views come from those services themselves.

  8. Everything runs on one small server

    Channel settings, outputs and stats are kept in data files on the same server rather than in a separate database, and sign-in goes through Auth0. There's only this one machine to look after, sized for one organisation rather than a large public site.

    8
